# 要件定義書 (REQUIREMENTS)

## 概要

ユーザーが Pico1W Resumaker の Wi-Fi アクセスポイント (AP) に接続した際、自動的に Web ブラウザが起動し、履歴書ページ (トップページ) が表示されるようにする（キャプティブポータル機能）。

## 目的

- ユーザー体験の向上: IP アドレス (192.168.4.1) の手動入力を不要にする。
- アクセシビリティの確保: QR コードを読み取れない、または読み取り機能がないデバイスでも、Wi-Fi 接続だけで履歴書を閲覧可能にする。

## セキュリティ方針

- 本プロジェクトの想定利用は、対面時に電源投入して即座に履歴書を提示する運用である。
- この運用では、保存データを暗号化しても、紛失した端末の電源を入れられて画面や QR コードから閲覧されることは防げない。
- そのため、主たる対策はデータ暗号化ではなく、端末の紛失防止、置き忘れ防止、持ち出し管理とする。
- データ暗号化を導入する場合でも、それは補助的な難読化または生データ読取対策として位置付ける。

## 機能要件

### 1. DNS ハイジャック (DNS Spoofing)

- デバイスからのあらゆるドメイン名解決要求 (DNS Query) に対して、Pico W 自身の IP アドレス (例: 192.168.4.1) を返すこと。
- これにより、OS の接続確認機能が特定のドメイン（例: `google.com` や `apple.com`）にアクセスしようとした際、強制的に Pico W の Web サーバーへ誘導する。

### 2. HTTP リダイレクト / キャプティブポータル検知対応

- OS ごとの接続確認用 URL へのアクセスを適切に処理し、トップページ (`/`) へ誘導すること。
- iOS, Android, Windows などの主要 OS の挙動に対応すること。
- 未知のパスへのアクセスや、IP アドレス以外（任意のドメイン名）でのアクセスがあった場合、トップページへリダイレクトすること。

### 3. パフォーマンス要件

- キャプティブポータルの判定処理が、通常の Web サーバーの応答速度やメモリ使用量に大きな悪影響を与えないこと。

### 4. コンテンツ表示要件 (Markdown 対応)

以下の項目について、Markdown 記法による記述と表示をサポートすること。

- 職務経歴の詳細 (`job_description`)
- ポートレイトの概要 (`portrait_summary`)
- 志望動機 (`usr_siboudouki`)
- 趣味 (`usr_hobby`)
- 特技 (`usr_skill`)

**制約事項:**

- クライアントサイドでのレンダリングを行う（Pico W の CPU 負荷軽減のため）。
- 外部 CDN に依存せず、ローカルにライブラリを配置してオフライン動作を維持すること。

### 5. 管理画面の認証

- `/admin/*` 配下の管理画面および管理操作は、未認証の状態では利用できないこと。
- BASIC 認証は使用しないこと。
- 認証済み判定は、ログイン成功時に発行するセッション Cookie により行うこと。
- ログイン画面は `/admin/login` に配置し、管理用パスワードの入力で認証すること。

**デフォルトの挙動:**

- 未認証で `/admin/login` 以外の `/admin/*` に GET アクセスした場合は `/admin/login` にリダイレクトする。
- 未認証で `/admin/*` に POST アクセスした場合は、保存処理を行わず認証エラーを返す。
- 認証済みセッションでは、既存の管理画面表示と保存処理を従来どおり利用できる。

**入力条件・制約・境界条件:**

- 管理用パスワードは `secrets.py` に定義する。
- セッションは Pico のメモリ上で管理し、本体の再起動時に失効する。
- ブラウザ側では Cookie を利用し、同一オリジンの通常アクセスを前提とする。
- 公開用の履歴書閲覧ページ (`/`) と公開 API の既存挙動は原則維持する。

**エラー時の挙動:**

- パスワード不一致時は 401 を返す。
- 管理用パスワード未設定時は、管理系エンドポイントに 503 を返す。
- セッション無効または期限切れ時は再ログインを要求する。
